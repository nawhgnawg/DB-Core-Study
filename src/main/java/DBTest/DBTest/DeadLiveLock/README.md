# 📌 [Chapter 1] 데드락(Deadlock)과 라이브락(Livelock)

## 💡 핵심 요약 (Key Concept)

### 1. 데드락 (Deadlock, 교착 상태)
* **정의:** 두 개 이상의 스레드/트랜잭션이 서로가 점유하고 있는 자원의 락을 얻기 위해 대기하며 **영원히 멈춰있는 상태**.
* **상태:** CPU를 소모하지 않음 (**Blocked / Waiting**).
* **발생 4가지 필수 조건 (Coffman Conditions):**
    1. **상호 배제 (Mutual Exclusion):** 한 자원은 한 번에 한 프로세스만 사용 가능.
    2. **점유 대기 (Hold and Wait):** 자원을 쥔 상태에서 다른 자원의 락을 요구.
    3. **비선점 (No Preemption):** 타 스레드가 점유한 자원을 강제로 빼앗을 수 없음.
    4. **순환 대기 (Circular Wait):** A는 B의 자원을, B는 A의 자원을 점유 대기.

### 2. 라이브락 (Livelock)
* **정의:** 데드락을 피하기 위해 자원을 양보하지만, 두 스레드가 동일한 타이밍에 계속 양보하여 **진척 없이 헛바퀴만 도는 상태**.
* **상태:** CPU를 계속 사용함 (**Active / Running**).
* **예시:** 무한 재시도(Retry) 충돌, 메시지 큐의 무한 재처리(Poison Pill).

---

## ⚖️ 데드락 vs 라이브락 비교

| 구분 | 데드락 (Deadlock) | 라이브락 (Livelock) |
| :--- | :--- | :--- |
| **스레드 상태** | 멈춤 (`Blocked`) | 계속 움직임 (`Active`) |
| **CPU 점유율** | 없음 (0%) | 매우 높음 (CPU 낭비) |
| **주요 원인** | 순환 대기 (Circular Wait) | 양보 및 재시도 타이밍 동기화 |
| **해결 전략** | **Lock Ordering** (획득 순서 일치) | **Random Backoff** (재시도 간격 무작위화) |

---

## 🛡️ 해결 및 예방 전략

1. **Lock Ordering (락 획득 순서 통일):** 모든 트랜잭션이 자원 A ➔ 자원 B 순서로만 락을 얻도록 강제하여 '순환 대기' 조건 파괴.
2. **Lock Timeout (타임아웃 설정):** 일정 시간 내 락을 얻지 못하면 예외를 발생시키고 기존 점유 락을 반납.
3. **Random Backoff (무작위 지연):** 충돌 시 즉시 재시도하지 않고, Random 지연 시간을 주어 타이밍을 엇갈리게 함.

## 💫 면접 대비 Q&A

**Q. 데드락 발생 조건 중 실무에서 가장 제어하기 쉬운 조건과 해결 방법은?**
> **A.** '순환 대기(Circular Wait)' 조건입니다. 애플리케이션 내 모든 로직이 동일한 순서로 자원 락을 획득하도록 **Lock Ordering** 규칙을 정하거나, DB 단위에서 **Lock Timeout**을 설정하여 선점 대기를 차단합니다.

**Q. 데드락과 라이브락의 차이점을 CPU 관점에서 설명해 주세요.**
> **A.** 데드락은 스레드가 `Blocked` 상태로 전환되어 CPU를 사용하지 않는 반면, 라이브락은 스레드가 `Running` 상태로 무한 루프나 재시도 로직을 수행하며 CPU 자원을 불필요하게 대량 소모합니다.
